## 一、人员现状与背景（0:00–1:45）

- **夏经理**：目前所有传票都由她写/下传票，负责整个传票环节。
- **李姨**（原商务对接人）：
  - 特殊情况：丈夫癌症较严重，基本不在公司，目前只能远程帮一帮忙、干一些自己的活。
  - 原职责：
    - 对接学校老师——所有电子版都发到她这里；
    - 平时做两件事：**合同**、**结算**；
    - 结算时需要把传票里的信息做成电子版，用于跟学校结算。
- **文颖**：李姨的活现在由文颖接手（就是刘总拉给沈老师的那个人），沈老师表示认识她。

## 二、双方方案陈述

### 2.1 沈老师最初的方案（1:47–4:56）——全量梳理路线

1. 按验收文档来录入。
2. 传票有多种模式：**生产传票**（最主要）、卖纸张、进货采购、废纸废品、复印费等，共**六七种**。
3. 流程：把每种传票的业务逻辑全部梳理出来 → 跟刘总核对 → 定下具体方案 → 按业务逻辑做程序 → 代码开发。
4. 生产传票先理主流程：**谁下单 → 下单后生产走哪些步骤 → 传票最终结束收到谁手里**；再理其他几种流程（目前大概知道六七种），全部理出来核对。
5. 核对完 → 设计阶段（每个传票怎么开发、怎么做）→ 跟刘总确认 → 具体开发 → 工厂试用每种传票，看是否合真实用途、哪里需要简化/复杂化。
6. **需要工厂配合的点**：沈老师定下流程后，工厂那边得有一个人去确认"流程 OK，我们就是这么做"；电子化好不好整，好整的话生产传票步骤就算定好了，后面照此开发。

### 2.2 刘总的分步方案（4:56–10:48）——最终采纳

刘总认为沈老师的描述偏概括，提出结合工厂工人实际情况的具体想法：

- **总目标闭环**：从**下传票 → 传票整理 → 形成结算信息**，这一条回路够了。
- **第一步（当前做）**：
  - 用**文颖**把过去两三个星期的传票录入成电子版；数据怎么录、什么要求，由沈老师提，文颖照做，保证给沈老师足够的信息；
  - 传票怎么给到沈老师：一张张拍照 / 邮寄 / 扫描（后定为扫描，见 §5）；
  - **夏经理暂时不动**，正常刷传票；他下完传票后，文颖负责把传票录入做电子版——相当于重复一遍，先繁琐一下；
  - 沈老师拿到数据后做信息处理，看能不能导出、做数据处理。
- **第二步（第一步可行后）**：
  - 让**夏经理**试用：下传票从原来的手写（无碳复写纸）变成**打印**；
  - 传票信息自动入库，自动按先前设计的格式输出。
- **不动的部分**：
  - **生产环节完全不连、完全不影响**：生产仍按纸质传票照旧流转；
  - 其他所有人都不动；
  - **不上学校自主下单 APP** 等任何额外系统。
- **验证目的**：现在所有测试都在下面完成（文颖试，不让夏经理实战试），新旧两套系统不调换；验证"传票录入系统后能跟生产上一一核对"，核对 OK，将来切换才不会有问题。
- **电子下单后的不变与变**：
  - 接单流程不变：文颖接单 → 把单的信息 + 要印的东西统一报给夏经理 → 夏经理形成传票；
  - 唯一变化：下传票由手写变成**录入计算机**，计算机连**针式打印机**（转写作"真式打印机"，应为针式）把传票打出来；
  - 系统里传票信息形成订单并储存，随时能查：**哪个学校印了多少、印了多少张纸、花销多少**。
- **节奏理念**：
  - 一步一步来，不一步到位；拆成小块让工人体验，每一步验证——一坨很多东西工人会嫌麻烦复杂；
  - 剩下的**所有复杂功能都不加**，先跑通闭环；
  - 顺便测工人的配合度，要简单、容易上手，让他们觉得"很简单、能用"；
  - 这个功能做出来工人**马上能用**、马上用得到，容易接受；
  - 用起来之后再慢慢往里加功能（如工人怎么用电子传票等是下一步的事）；
  - 本闭环相当于先完成**夏经理和李姨两人工作中的一部分**；
  - 顺序：先做**李姨的结算功能** → 再走向**夏经理的功能** → 最后让夏经理真正用系统下传票。

## 三、达成的共识与关键决策

| # | 决策 | 备注 |
|---|---|---|
| 1 | **范围锁定：只做生产传票** | 刀切纸、进货采购、废纸废品、复印费等其他传票全部放一边 |
| 2 | **对账只对生产传票** | 跟学校对账主要就是生产传票；其他传票是内部运营记录，不跟学校对 |
| 3 | **数据采集期：最近两周** | 约五十张生产传票（所有传票一个月上百张） |
| 4 | **采集方式：文颖扫描** | 一张张按**日期和顺序**扫描；拍得清晰仔细也行；**不邮寄**（费时间） |
| 5 | **扫描范围：两周内所有传票都扫** | 先从里面把生产的挑出来给沈老师，其他的分类放一边——不丢东西；以后沈老师边干有灵感可随时把某类加进来 |
| 6 | **录入表格由沈老师设计** | 目的：方便后续筛选、归纳、检索、数据整合；可双方一起设计；Excel 填表或小程序录入待定 |
| 7 | **分步实施、最小闭环优先** | 先"录入→处理→出结算数据"，再电子下单，最后连生产；复杂功能一律后加 |
| 8 | **费用按实际工作量** | 刘总看过沈老师发的方案/报价，觉得都不大碍；最终根据实际工作内容由沈老师出价格；双方是朋友，先往前走 |

## 四、传票信息字段（沈老师提出的关注点）

一张传票里涉及的信息（待拿到实物后逐项确认）：

- 学校信息
- 老师的信息
- 联系方式
- 有哪些**工序**
- 传票号（刘总建议表格里写上传票号，可一比一还原）
- 纸张、规格等（见沈老师"口述"设想中的例子：传票用什么纸、什么规格）

## 五、表格与录入方式（当前最关键的待办）

- 刘总观点：**这个表格是现在比较重要的一个**。两种思路：
  1. 按传票原格式一比一还原，做一个表格让文颖一张张填；
  2. 由沈老师设计一个便于后续筛选/归纳/检索的表格，工厂照填；也可以设计过程中一起设计。
- 录入载体待定：**Excel 填** vs **沈老师做一个小程序一个个填**。
- 沈老师的远期设想（本期不做）：**口述录入**——文颖口述一段话（什么纸、什么规格等），语音转文字贴给沈老师，直接生成表格；涉及 AI 解析，不一定现在能做。**保底方案**：沈老师做表格，工厂填完给他，直接生成数据。
- 刘总态度：现在不用做那么高级，笨一点也行，稍微花点时间也行。
- 沈老师拿到传票后流程：整理所有传票信息 → 问细节（各字段什么意思）→ 整理出一个比较全的表格（Excel 或别的模式），保证工厂方便填写。

## 六、后续愿景（讨论中提及，未排期）

- 每个学校累计印了多少、用了多少纸，随时可查；结算时系统直接出数据。
- 传票方式形成订单，逐步把生产环节的新方式接入。
- 一步步叠加功能，最终实现从下单到结算的完整电子化。
- 口述 → AI 解析 → 自动生成录入（沈老师的最终形态设想）。
