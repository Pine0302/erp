# 说话人映射与依据

> 本文件汇总 8 份腾讯会议转写中识别出的实际说话人、所用证据，以及跨文件人物对应关系。所有判断均基于文本（原始转写 + 疑问点清单 + 会议 detail/summary），未做音频声纹验证。

---

## 一、方法与背景

### 1.1 资料使用分工

| 资料 | 用途 | 限制 |
| --- | --- | --- |
| 我的背景补充（任务描述） | 提供已知人物、岗位、会议背景 | 仅作背景依据，不可作为归属证据 |
| 疑问点清单 `metting/疑问点清单.docx` | 提取 Q 编号、问题正文、章节结构；帮助定位正在讨论的话题 | 清单中的"答案"不等于会议原话 |
| 会议 detail（5 份） | 通过语义对齐辅助识别发言中的人物；可识别提问/回答关系 | 描述 ≠ 逐字转写；不可补写原始发言 |
| 会议 summary（5 份） | 辅助理解整体议题和查找线索 | 同上 |
| 原始转写（8 份） | 真实存在的发言文本、顺序、时间和原始说话人标签 | 同音词、错字、断句错误和口头语 |

**不得互相替代**：清单中的答案 ≠ 会议原话；detail 中的描述 ≠ 逐字转写；岗位职责 ≠ 某段发言的归属证明；同一议题在清单、summary、detail 中可能多次出现，不应叠加为多重证据。

### 1.2 核心方法

1. 完整读取疑问点清单，提取 Q 编号、章节、备注，识别已填答案与原始问题；
2. 将原始对话按 Q 编号或章节定位（通过相同问题、例子、问答关系与上下文）；
3. 与对应会议 detail 做语义对齐（不仅是关键词），找到可靠对应关系；
4. 在对应位置利用 detail 中明确标注的人物辅助归属。

### 1.3 说话人识别规则（简述）

- 标签是文件内编号，S01、S02 等不跨文件统一身份；
- 同一文件中允许"默认映射 + 局部例外"，例外必须有具体片段与依据；
- 优先寻找身份锚点（自我介绍、直接称呼、发言交接、入离场、第一人称职责、连续问答）；
- 话题、语气和语言习惯仅作弱辅助，不得单独决定身份；
- 区分实际发言与人员提及（被介绍员工不一定发言，介绍后的下一段话也不一定属于被介绍者）；
- 姓名、称呼、岗位分别判断，不补全姓名；
- 置信度高/中/低描述判断依据强弱；高可直接使用规范称呼，中显示"推定"，低保留原始标签并显示"待确认"。
