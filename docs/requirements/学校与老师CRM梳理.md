# 学校与老师CRM梳理

整理日期：2026-10-21。本文整理现有资料中的学校、校区、老师和联系人关系，并区分历史完整方案与当前生产传票阶段。内容为需求讨论依据，不表示相关功能已经实现，也不是数据库设计。

当前样票只用于理解业务及后续录入设计，不处理该批数据，也不为其建立学校、老师名册或补齐姓名。

## 一 这部分CRM承担什么

现有资料中的CRM主要承担客户及人员基础资料维护：认清业务属于哪所学校、哪个校区、哪位老师，由谁联系，再供生产传票归属、查询和汇总使用。历史完整方案还关联学校账号、合同、价格和查看权限。

用户已明确本期不做订单，从生产传票开始。最新会议也明确暂不上学校自主下单端，学校和老师的信息由内部录入、整理。老师资料是否存在，与老师是否拥有登录账号，应分开讨论。

依据：[当前沟通纪要](../../metting/meeting-notes.md)第四节；[原转写JSON](../../metting/transcripts/meeting-notes.json) `seg_0075`、`seg_0087—0088`；用户本轮范围说明及[生产传票专稿](生产传票分类与录入导出梳理.md)第一节。

## 二 学校及人员的关系

| 对象或信息 | 资料中的含义 | 需要分清的关系 |
|---|---|---|
| 学校 | 客户及学校业务汇总的归属对象 | 一所学校可能有多个校区、学部、驻点或有效合同，不能限定成一校一校区或一校一合同 |
| 分校／校区 | 学校业务的具体组织、地点信息 | 各校叫法不同；与学校全称及票面简称分别核对 |
| 学部、年级、学科、学科组／组长 | 老师和印刷业务的描述、联系及分发维度 | 资料提出需要保留这些信息，尚未统一确认所有层级都要建成正式组织树 |
| 学校老师 | 实际提出或使用印刷品的人，也可能承担联系、确认或领取职责 | 所属学校、校区与具体业务需能对应；不能仅凭姓名跨学校合并人员 |
| 学校印务经办人 | 部分学校指定一名老师集中收集需求、对接工厂 | 经办人可能与实际使用老师不同，不能把所有业务都记成经办人本人使用 |
| 驻点 | 印刷厂设在学校内的生产服务点 | 一校可有多个驻点；驻点是生产组织，校区是学校信息，不能直接视为同一对象 |

学校组织维度来自[订单流程调研](../../现状业务流程_AS-IS/订单流程业务调研.md)第五节及第7.1—7.2节；驻点与学校的关系来自[驻点调研](../../现状业务流程_AS-IS/外围驻点流程业务调研.md)第2.1—2.2节。

上表描述业务含义，不要求每个称谓都单独建表，也不表示老师与校区、年级、学科之间的数据库约束已经确定。

## 四 实际老师 经办人和录入人要分清

现有资料同时描述了两种业务方式：老师各自联系工厂，以及学校指定专人统一办理。有实际需求老师信息时应保留，以便核对要求及追溯；用户最新允许老师姓名缺失时暂空，年级、学科和联系方式等选填。

| 人员含义 | 说明 |
|---|---|
| 实际需求／使用老师 | 这项印刷品实际给谁使用，相关业务应归到谁 |
| 校方经办人 | 谁收集需求并对接工厂；可能替其他老师办理 |
| 工厂实际录入人 | 历史资料描述过商务、文颖、驻点人员等可能的录入岗位；用户最新明确未来由夏直接在系统录入。录入人身份不能据此当作校方需求老师 |

这是对业务身份的区分，不要求同一项业务一定有三个不同的人。原票没有写清时保留缺失或待核，不补造使用人。

依据：[订单流程调研](../../现状业务流程_AS-IS/订单流程业务调研.md)第5.1—5.2节；[疑问清单](../../metting/疑问点清单.docx)Q-1.3.1明确回复可以用“下单人、使用人”区分；[驻点调研](../../现状业务流程_AS-IS/外围驻点流程业务调研.md)第三节及第5.1节。

另外，会议中的工厂财务、驻点员工也可能被称为“某老师”。称谓本身不能证明其为学校教师，整理学校老师资料时要按实际身份核对。

## 五 学校权限和配额的历史讨论

早期方案曾提出老师查看本人业务、组长查看本组业务、学校负责人查看全校业务，以及老师身份审核等能力。会议1讨论后，组长等校方管理角色被放到后续；当前最新范围进一步明确不做学校自主下单端。不能把旧规格中的完整角色体系直接作为本期范围。

个人配额也有前后差异：总体需求曾讨论给老师参考配额，但会议1随后明确当前没有细到每位老师的分配，总量给总校，尚不具备按教师精细分配的实际做法。因此，不能将“每位老师都有个人额度”或“超额自动禁止下单”当作已确定规则。

内部按老师整理数量、金额，与学校老师能否登录查看这些金额，是两个决定。用户已确认导出时可选择学校及已有学部等组织范围，或该学校的具体老师；不能因为旧稿写老师端隐藏价格，就删除内部资料中的价格及归属。

依据：[会议1原转写](../../metting/transcripts/会议1-asr.txt)29:49—31:47、33:32—36:37、39:17—39:44；[疑问清单](../../metting/疑问点清单.docx)Q-1.4.1—Q-1.4.2；[当前沟通纪要](../../metting/meeting-notes.md)第二节。

## 六 与当前传票录入怎样衔接

本版填写要求已由用户于2026-10-21确认并补充：学校名称必填；老师姓名原则填写，缺失时允许暂空，不要求先补齐才能录入。其余学校及老师资料，包括校区、学部、年级、学科、学科组、组长、联系方式等，均为选填。样票仅用于理解规则，不要求补齐其中的学校、老师资料。

2026-10-22用户调整并确认档案维护方式：学校、老师档案的增删改查放在后续后台；录传票时，各项印刷品只选择已有学校及该校老师，不再保留整票默认学校、老师，也不随录票自动新增档案。此决定取代此前“提醒后随传票新增”的方式。老师缺失仍允许暂不选择，本轮不实施后台。

老师匹配规则已由用户确认：按“学校＋姓名”查找已有老师记录，不同学校的同名老师分别保留，不跨学校仅凭姓名合并。

学校名称归并规则已由用户确认：同一学校的全称、简称归到同一个学校档案，每张传票同时保留原票上的名称。老师匹配使用归并后的学校档案，不因同一学校的不同写法重复建立老师记录。实际全称、简称的对应关系需结合学校名单整理。

以下整理已确认的选择、匹配和后台维护要求，以及其余关联建议，尚未进入正式字段规格或数据库设计。

| 信息 | 当前处理 |
|---|---|
| 学校名称（必填） | 每项印刷品选择已有学校；同校全称、简称关联同一学校档案，归并关系由后续后台维护 |
| 老师姓名（缺失可暂空） | 选择该校已有老师，跨学校同名分别记录；缺失允许不选，不从学科、品名或识别候选补造姓名 |
| 学校／老师记录不存在时 | 去后续后台新增档案；录票页不自动新增、修改或删除学校及老师档案 |
| 校区／分校（选填） | 有明确校区就记录，学校没有或原票未写时不强行补层级 |
| 联系方式（选填） | 有据可录时补充，不作为保存学校及老师资料的必填条件 |
| 实际业务归属 | 在传票明细上保留学校、校区、老师；一票跨学校或多老师时分别识别，不全部归给票头单位或某一联系人 |
| 导出范围（已确认） | 按订货日期选择期间后，可按学校整体、已有校区／学部等组织信息选择范围，或选该校具体老师导出其明细 |
| 经办与使用身份 | 遇到集中办理且资料能够区分时分别记录；实际录入人单独表达 |
| 组织维度（选填） | 学部、年级、学科、学科组、组长等按已知信息填写；已有学部等组织信息可用于选择学校导出范围，不要求建完整组织树才能导出 |
| 老师账号 | 保存老师信息本身不要求老师有登录账号，学校端账号另按后续范围讨论 |

095票的已知对应关系是：学校“东城”；“东校”为校区；八、九年级作文纸分别对应票面老师，两项各1000份。两项可以共用机印记录及合价记录，产品和老师的归属仍分别表达。这个例子用于说明关系，不要求辨认并补齐样票老师姓名。

本版统计按订货日期归期，材料统一按预计用纸量处理；这两项已由用户确认。细节见[生产传票专稿](生产传票分类与录入导出梳理.md)第三、四、七节。

## 七 后续录入设计的讨论事项

1. 后续后台提供学校、老师档案的增删改查，具体页面与接口到相关阶段再设计；录票明细只选已有档案。不以建立本批样票的完整名册为前提。
2. 导出具体列、版式及经办老师与使用老师在输出中的呈现方式；按学校、已有学部等组织范围或该校具体老师选择导出的方式已确认。

上述事项用于后续讨论，不作为扩大CRM范围或进入系统开发的授权。
