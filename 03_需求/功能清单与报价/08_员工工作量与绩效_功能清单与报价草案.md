# 员工工作量与绩效｜功能清单与报价草案

> 文档状态：内部评估稿，供客户按需选择；尚非正式报价或已确认需求基线。  
> 整理日期：2026-09-26  
> 模块定位：**整体选配**。基础包处理工作量复核和月度工资金额台账；自动计件、质量评分等另列增强项。  
> 金额单位：人民币元。

## 1. 为什么将本模块单列为选配

前七个报价单元已覆盖生产逐人报工、工作量查看、基础异常、配送人员记录及财务费用登记。本模块若被客户选中，主要解决**月底确认每人做了哪些工作、调整是否留痕、每月工资是多少、工资费用如何进入月度经营汇总**。它引用前述数据，不再开发一套生产报工或订单业务量系统。

现有资料支持的事实和边界：

- 总厂目前主要靠人工记录工作量，月底翻查纸质传票汇总；胶印“转”、装订“册”等工序单位不同。生产模块 P05、P06、P13 已报价逐人报工、接替及工作量汇总。[总厂生产流程调研](../../02_业务调研/现状业务流程_AS-IS/总厂生产流程调研.md)、[生产流程报价草案](./04_生产流程_功能清单与报价草案.md)
- 会议 5 一线人员说明，中途换人可能由员工自行沟通，现状并不逐次记交接工作量；未来 P05/P06 能记录，并不代表可把旧纸票自动准确拆给每个人。[会议 5-part1 原始记录](../../02_业务调研/沟通记录/会议5/会议5-part1-说话人标注版.md)
- 会计提出希望能单列每月工资，以及查看生产、原材料和其他费用。访谈没有给出工资结构、计件单价、奖惩规则、考勤口径或工资审批链。[会议 5-part3 会计访谈](../../02_业务调研/沟通记录/会议5/会议5-part3-说话人标注版.md)
- 总厂与驻点协同任务的成本及绩效归集由生产经理决定，但具体分配算法未定。驻点业务工作量、总厂后加工工作量和客户计费数量是不同口径。[外围驻点流程业务调研](../../02_业务调研/现状业务流程_AS-IS/外围驻点流程业务调研.md)
- 维修师傅绩效属于客户提出的未来诉求；现有 I16 只有基础报修申请，I-O04 才涉及维修派工与费用。不能在缺少维修工单和规则时承诺自动计算维修绩效。[库存与耗材报价草案](./06_库存与耗材_功能清单与报价草案.md)

**建议客户选择方式：**如果一期只要求知道“每人完成多少工序工作量”，直接使用生产模块 P13，无需购买本模块。若还需要按月复核并保存工资金额，则选择下文基础包。自动计算计件绩效、考勤和质量奖惩，等真实规则及样本齐备后逐项增购。

## 2. 本轮报价假设

1. 基础包使用已有员工账号、公司、地点、生产工序及报工记录；不重复建设员工人事档案、生产任务或逐人报工。
2. 工序工作量按原单位分别汇总，例如“转”“册”“张”，不把不同单位简单相加为一个“总产量”。总厂、驻点协同或换岗后的工作量归属由授权人员按实记录/复核，不内置尚未确认的自动分摊比例。
3. 月度工资金额可人工录入或按经确认的表格导入，基础包提供工资项目和合计、审核及更正留痕；不自动推算计件工资、个税、社保、公积金或银行代发文件。
4. 财务单元 F10 已有日常费用登记；本模块提供按公司、月份确认的人工费用汇总供财务引用，工资不能在两个模块各入一遍形成双倍费用。实际付款、应付工资总账及法定薪酬申报不在本估算内。
5. 员工仅查看其获准查看的工作量；工资明细默认仅由指定工资经办人与授权管理人员查看，具体角色由客户确认。
6. 沿用前七个报价单元的暂估参数 **300 元／计价工作日**；明细价格按原估人日 ÷ 3 折算计价工作日；目标排期另按 4.8 倍效率测算，见[报价总览](./00_功能选配与报价总览_对客讨论稿.md)。原估人日包含本模块需求细化、页面与接口开发、测试及缺陷修正；不是独立市场询价结果。

## 5. 与其他报价单元的分工

| 事项 | 归属 |
| --- | --- |
| 员工账号、基本角色和公司信息 | 基础平台与合同计价；本模块仅设工资信息的专门查看权限 |
| 工序任务、个人报工、多人接替和基础工作量汇总 | 生产流程 P05、P06、P13；本模块引用、月度复核并保留调整记录 |
| 打包、送校和签收业务事件 | 交付配送；如未来纳入配送绩效，须先确认驾驶员/协作人员的统计规则，基础包不重复计配送业务量 |
| 设备报修及实际维修过程 | 库存与耗材 I16、I-O04；本模块的维修绩效选项只引用有依据的维修工作量 |
| 工资形成与个人工资明细 | 本模块；基础包为人工金额台账，自动计件仅在 H-O01 |
| 月度费用、付款及经营财报 | 财务与结算 F10/F13；本模块提供工资汇总来源，不建设第二套费用账或会计总账 |
| 客户计费量、合同收入和订单材料成本 | 合同计价、财务、库存；个人工序工作量不能直接当客户收入或订单人工成本 |

## 6. 建议验收场景

1. 1000 册装订由 A、B、C 分别完成 300、300、400 册；生产模块已记录三人的报工。本模块读取并按月汇总，合计与原任务一致，不要求员工再填一遍 1000 册。
2. 一名员工中途被替换，现状旧纸票没有逐人数字，系统标注“历史归属待核”；新业务按 P05/P06 记录后，由授权人复核，不凭整张传票数量自动平均分给两人。
3. 同一人本月胶印 500 转、装订 200 册，月报分别列示两种单位，不给出“总工作量 700”的误导性数字。
4. 工资经办人录入某员工本月已确认工资总额及组成，财务仅收到该公司本月汇总金额；员工本人及普通生产经理不能查看无权限工资明细。
5. 月度工资确认后发现一笔手工金额录错，生成更正记录并保留原值；财务汇总同步使用最新确认版本，不把更正前后金额累计两次。
6. 驻点印刷、总厂装订同一批产品时，各人员的工序工作量分别归属；客户订单数量仍只计算一批，不因跨地点而增加收入。
7. 若客户另选自动计件，以一份真实工资表和确认的工序单价验收计算结果；无单价或口径未确认的工序保持待人工处理，不输出虚假的自动工资。

## 7. 报价前必须核对的资料与问题

| 核对项 | 对范围或价格的影响 |
| --- | --- |
| 一份真实的月度工作量统计表及对应传票、工序报工样本 | 确认 H01/H02 是否能沿用 P13，核对不同工序的单位和历史补录难度 |
| 一份脱敏工资表、工资项目说明和各员工所属公司 | 确认 H03/H04 字段与导入模板；工资组成不能由访谈中的“每月工资”自行推断 |
| 工资经办、审核、员工自查、财务可见范围 | 决定 H05/H08 角色和导出权限，避免对普通生产岗位暴露个人工资 |
| 一笔多人接替及一笔总厂/驻点协同的真实工作量归属 | 确认 H02 的人工判断节点；生产经理决定归集，不等于已有固定计算公式 |
| 工资费用目前在月度财务记录中怎样登记、按吉星/津金怎样归属 | 确认 H06 与 F10 的去重及公司边界 |
| 若选择自动计件：工序单价表、计件基数、多人分摊、返工、跨月和保底规则 | 决定 H-O01 能否按一套规则报价；缺失样本时不应承诺自动算工资 |
| 若选择质量奖惩：实际返工、责任确认和工资调整实例 | 确认 H-O02 依赖 P-O02 的记录及合法、可执行的内部制度 |
| 若选择维修绩效：报修、接单、修复、费用与维修人员记录 | 确认 H-O04 是否已有 I-O04 所需的完整工单来源 |

## 8. 报价使用说明

本草案按“原估人日 ÷ 3 × 300 元／计价工作日”暂估。可参考国家标准[《软件工程 软件开发成本度量规范》GB/T 36964-2018](https://std.samr.gov.cn/gb/search/gbDetailed?id=7E2903B0D6E05A63E05397BE0A0AF660)的成本度量思路；本表未完成正式功能点规模测量，**不能称为依据该标准算出的正式报价**。正式商务报价应在工作量与工资样本、隐私权限、一期选配范围、薪酬规则、部署及验收边界确认后形成。
