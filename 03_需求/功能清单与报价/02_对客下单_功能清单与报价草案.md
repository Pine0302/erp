# 对客下单｜功能清单与报价草案

> 文档状态：内部评估稿，供逐项与客户讨论；尚非正式报价或已确认需求基线。  
> 整理日期：2026-09-26  
> 报价单元：对客下单；依赖[基础平台与合同计价](./01_基础平台与合同计价_功能清单与报价草案.md)。  
> 金额单位：人民币元。

## 1. 报价目标与业务依据

本单元让老师、商务、总厂和驻点以各自身份记录印刷需求，形成可追溯的电子订单，并将订单交给总厂传票或驻点生产环节。订单需要记录**实际需求老师、实际录入人、来源、稿件类型、学校及合同归属**，但订单与总厂纸质传票不是一一对应关系。

已知业务事实与边界：

- 现状以微信、电话、纸稿、电子稿等渠道提出需求；老师线上自助下单是拟建能力，不能当作现行流程。
- 学校业务应能追溯到具体老师；商务、总厂或驻点代录时使用自己的账号，不冒用老师身份。
- 驻点普通试卷、复印、速印业务通常自行完成，不生成总厂生产传票；需要总厂协作时才进入后续传票和生产流程。
- 学校印刷申请单可当次交，也可事后补交；一张申请单可能对应多笔实际业务，补录凭据不能再生成一笔生产量或应收。
- 老师端不显示价格或自选“加急”；加急由生产经理内部协调。合同内价格、特殊计价依据与权限基础由上一报价单元提供。
- 代录后的老师确认、线下签字、紧急处理和驻点快速生产之间存在尚未统一的口径，报价包含记录确认与例外依据的基本能力，具体生产放行规则仍须用实例确认。

主要依据：[订单流程业务调研](../../02_业务调研/现状业务流程_AS-IS/订单流程业务调研.md)、[外围驻点流程业务调研](../../02_业务调研/现状业务流程_AS-IS/外围驻点流程业务调研.md)、[会议3原始记录](../../02_业务调研/沟通记录/会议3/会议3-说话人标注版.md)、[会议6驻点访谈](../../02_业务调研/沟通记录/会议6/会议6-驻点高老师-说话人标注版.md)。

## 2. 本轮报价假设

1. 老师端以**手机网页（H5）**为必选入口，内部人员使用适合电脑或手机浏览器的页面；原生微信小程序单列选配。B03 已报价的账号及基础权限直接复用。
2. 一期以学校业务为主要标准流程，同时支持商务或总厂人工录入非学校客户订单；石化总厂的逐项合同履约规则、社会散客收银流程仍需专项核对。
3. 电子稿支持上传常见文件并关联订单；纸质稿可只登记类型和交接信息，**不强制生产前扫描成电子文件**。文件容量、存储期限及部署资源需在正式报价时确定。
4. 报价包含基本订单状态、确认记录和内部交接；工序、传票、配送凭证及财务结算由各自模块负责，订单端读取其结果展示。
5. 仍沿用前一单元的暂估参数 **300 元／计价工作日**；明细价格按原估人日 ÷ 3 折算计价工作日；目标排期另按 4.8 倍效率测算，见[报价总览](./00_功能选配与报价总览_对客讨论稿.md)。原估人日包含本单元需求细化、页面与接口开发、测试及缺陷修正。

## 5. 与其他报价单元的分工

| 事项 | 归属 |
| --- | --- |
| 公司、学校、老师账号、角色、合同、合同价格与计价规则 | 基础平台与合同计价；本单元仅调用，不重复报价 |
| 订单中发起、记录需求及处理变更 | 对客下单；生产经理操作界面和订单变更留痕在本单元 |
| 一张或多张总厂传票如何承接订单、票内多产品／多学校、生产工艺 | 传票及生产模块；本单元只提供订单数据与关联入口 |
| 驻点生产量、设备、耗材与总厂协同执行 | 驻点／生产及库存模块；本单元仅提供驻点订单入口和分流 |
| 包装、分批送货、照片及签收 | 交付配送单元；订单端只读取并展示概略状态 |
| 实际业务明细、折算后最终结算金额、对账、发票和回款 | 财务结算模块；本单元保留需求和拟计价依据 |

合同额度预计占用、取消释放和交付后正式扣减为**跨模块联动项**，待订单、交付和财务模块口径核对后统一报价；D06 不包含额度账本或自动扣减。订单取消若已形成传票或发生生产，传票作废、已发生成本和费用归属也须在后续模块确认。

## 6. 建议验收场景

1. 老师上传电子试卷并下单，订单归属正确学校与老师，老师端可见状态但看不到合同价格，也不能自行标记加急。
2. 商务接到微信需求后代录，订单同时记录老师与商务本人；老师确认记录可追溯，未确认时不伪装成老师自助下单。
3. 老师送纸稿到驻点，驻点快速登记后自行生产普通试卷；订单留在后台，但不被强制生成总厂传票或先上传扫描件。
4. 驻点已完成三笔印刷后，补传一张涵盖三笔业务的学校申请单；系统只增加凭据关联，不再增加印刷量或金额。
5. 老师提出取消或修改，生产经理能查看请求并记录处理结果；已进入生产的订单不会被无提示地直接删除。
6. 合同外产品按合同品项折算时，仍能查看老师原始需求、实际产品和折算说明；最终计费以财务模块核实口径为准。

## 7. 报价前必须核对的资料与问题

| 核对项 | 对范围或价格的影响 |
| --- | --- |
| 一笔老师自助、一笔商务代录、一笔驻点业务的原始需求与交付样本 | 核对表单字段、操作步数和分流路径 |
| 代录订单确认凭据及紧急生产实例 | 明确线上本人确认、现场签字、授权例外分别何时允许生产 |
| 学校申请单样本及后补过程 | 明确申请单与订单的关联规则、照片上传责任人 |
| 已开始生产后的修改、取消及补印实例 | 明确订单、传票、产量与费用如何处理，决定是否扩大 D07 或选择 D-O03 |
| 老师端目标载体及文件规模 | 若客户要求微信小程序作为首发必选入口，需将 D-O01 并入一期；大文件存储费用另测算 |
| 石化、散客、固定散户的真实下单与收款样本 | 目前仅报价基础人工录单，专项交易规则需另行估算 |

## 8. 报价使用说明

本草案按“原估人日 ÷ 3 × 300 元／计价工作日”估算，可参考国家标准[《软件工程 软件开发成本度量规范》](https://std.samr.gov.cn/gb/search/gbDetailed?id=7E2903B0D6E05A63E05397BE0A0AF660)的成本度量思路；本表并未完成正式功能点度量。税费口径、部署资源、文件存储、第三方平台费用和历史数据迁移须在正式商务报价中明确。
